# Проверка JSON-импорта и экспорта

## Перед выпуском

Из корня репозитория выполнить `bash scripts/tests/repository.sh`, `bash scripts/tests/frontend.sh` и `bash scripts/tests/dotnet.sh` в среде с Node/npm и .NET 10. Модельные тесты не заменяют production build и браузерный E2E.

Новый клиент использует POST `/api/courses/{id}/assignments/import-json/preview`. Проверка UUID курса использует read-only POST `/api/internal/courses/import-probe`. Обновлять education-api перед tasks-api, затем front. Для обработки недоступного Telegram-получателя обновить support-api перед support-bot.

## Приёмка в отдельном скрытом курсе

1. Официальный мега-пример применить одним импортом. После перезагрузки и полного экспорта должны сохраняться 17 связей, 14 размещённых узлов вместе с корнем и ровно один намеренный черновик вне карты. Повторное сохранение этапа карты не создаёт сущности.
2. К корню с существующей исходящей связью добавить новую задачу и стрелку без layout. Проверить сохранность старой ветки, размещение новой задачи и отсутствие наложения карточек. Повторить для вложенного курса.
3. Искусственно отклонить PUT карты после успешного POST импорта. Окончательного уведомления об успехе быть не должно. Проверить сообщение о частичном результате и кнопку повтора только карты, затем сохранение после восстановления связи.
4. В Preview выключить связи и эффекты, удалить connections из JSON. Импорт не должен требовать массив-заглушку или снимать существующие узлы с карты. Для v3 проверить пустой datasets и явно ограниченный scopes.
5. Сравнить режимы замены и добавления на одной ветке: merge сохраняет старые рёбра; replace перечисляет реальные удаления и требует разрешения. Цикл вместе с сохраняемыми рёбрами блокируется.
6. Проверить UUID задачи и курса, занятые вне поддерева: Preview блокируется без создания/переноса сущностей. Свободный UUID с полным описанием допускается; отсутствие course у существующей задачи сохраняет фактического родителя.
7. Импортировать только позицию корня и отдельно viewport. Число операций должно отражать изменение; координаты/масштаб должны пережить перезагрузку. Выключенный layout ничего не перемещает.
8. Проверить экспорт: ID или content обязательны; partial checks/content/visibility/access/layout сохраняют выключенные категории. Без сохранённой карты экспорт не строит линейную цепочку сам.
9. Для SQL проверить reused/created dataset в Preview. У новой SQL-задачи полный spec сохраняется даже при выключенных переключателях обновления существующих. Проверить реальное выполнение SQL и состояние новой ревизии отдельно.
10. В тестовой доставке поддержки смоделировать 403 получателя. Ответ остаётся в поддержке, не получает статус доставленного, исключается из очереди Telegram как недоступный; следующий получатель обрабатывается. Временные ошибки сети не трактуются как запрет получателя.

## Границы гарантий

Курсы, задания и карта сохраняются разными этапами. Общей распределённой транзакции нет. После сбоя нужно проверять журнал и продолжать ту же операцию, а не создавать новый импорт. Прекращение операции не откатывает уже сохранённые данные. Правила находятся в `expected-behavior.json` и в guide экспортируемого файла.

# Solutions API EF projection build fix

Fixed `services/solutions/api/Program.cs` after the monolith parity transfer.

The previous version used local helper functions such as `BadgeDto(...)` and `ImageDto(...)` directly inside EF Core query projections:

```csharp
query.Select(x => BadgeDto(x)).ToListAsync();
```

This cannot compile because EF builds an expression tree for `IQueryable`, and expression trees cannot reference top-level local functions.

Fix:
- materialize EF queries with `ToListAsync()` first;
- apply local DTO helpers in memory with LINQ-to-Objects;
- keep response shape unchanged.

Affected endpoints:
- `GET /api/badges`
- `GET /api/badges/user/{userId}`
- `GET /api/me/image-solutions`
- `GET /api/admin/users/{userId}/image-solutions`

No migrations were generated by this fix.

# Обновление страницы кластера

Основа: пользовательский архив taskforge-develop(204).zip, исходный коммит 98857255ee4afb182a32fbe1a0eb46e5dcd0ba55. Это полный архив исходников приложения, не новый серверный release.

## Что устанавливать

Обновляются два образа: `front` и `observability-api`. Сначала желательно обновить API, затем фронтенд. Установленные Node Agent A/B/C остаются на **r57**. Команда `cluster.sh migrate` для этого обновления не требуется. Токены Cloudflare, сертификаты, PostgreSQL, volumes, WireGuard, роли full/lite и переключение Primary не меняются.

Старые `deploy/cluster` и `deploy/prod` внутри исходного ZIP оставлены без изменений. НЕ используйте их вместо уже установленного серверного r57 и не запускайте из них миграцию ради этой страницы.

Обычный путь: внести изменения из архива в репозиторий, проверить diff, отправить в рабочую ветку и дождаться сборки/развёртывания двух образов. Ничего в GitHub от вашего имени этим обновлением не отправлялось.

Для ручного запуска существующего GitHub Actions workflow `docker images`: `build_all=false`, `images=front,observability-api`, `debug_logs=1`. Переключать Primary ради обновления страницы не нужно. После обновления обоих образов открыть `/admin/cluster` и обновить страницу. Для этой задачи не требуется новая БД или миграция схемы.

## Интерфейс

Компактная сводка заменяет пять растянутых плиток. Карта занимает 560–740 px по высоте на обычном экране; есть полноэкранный режим, масштаб, вписывание, MiniMap, автоматическая расстановка и блокировка перемещения. Узлы по умолчанию подвижны. Координаты и масштаб сохраняются локально в браузере для данного кластера; опрос телеметрии их не сбрасывает. Кнопка «Расставить» восстанавливает рассчитанную раскладку. Перемещение узла — только оформление, оно не меняет топологию или роли серверов.

На узлах видны public IP, WireGuard IP, профиль, роль, готовность и количество подготовленных контейнеров. Адреса копируются отдельной кнопкой. Слои карты: обзор с Cloudflare, PostgreSQL, MinIO, WireGuard. Топологические связи MinIO/WireGuard не выдаются за измерение здоровья репликации/канала.

У выбранного сервера три вкладки: обзор, контейнеры, сеть. Контейнеры доступны в таблице с поиском и фильтрами. Остановленные подготовленные приложения standby не окрашиваются как авария. При устаревшей телеметрии выводится предупреждение; старые данные не объявляются свежим доказательством готовности.

Добавлены подробности Cloudflare/HTTP/TLS, публичные проверки по доменам, причина ожидания, выбранный origin и использование существующего сертификата. Есть матрица образов и фильтруемая лента событий. Опрос можно поставить на паузу; в скрытой вкладке лишние запросы не отправляются.

## Исправления преобразования данных

`observability-api` нормализует существующую телеметрию r57 и сохраняет совместимость с прежними объектными списками сервисов. Новых сетевых или управляющих API нет; используются прежние административные GET-маршруты.

- Строковые `docker.services` превращаются в записи сервисов, а `status` / `restart` — в ожидаемые состояние и число рестартов.
- IP извлекаются из уже доступной топологии. Сырые ключи WireGuard, API-токены и конфигурация Cloudflare в новый публичный контракт не передаются.
- Плоские показатели диска r57 преобразуются в используемый/доступный объём. При этом использование включает системный резерв и так подписано.
- Для standby отсутствие локального сертификата не становится самостоятельным поводом объявить кластер неисправным. Готовность приложения/БД/MinIO и прочие реальные проверки сохраняются.
- Несколько свежих Primary отображаются как конфликт, без произвольного выбора A. Последние, но устаревшие снимки не участвуют в определении текущей Primary.
- События без ID получают устойчивый идентификатор, `detail` показывается как сообщение. Механизм отправки Telegram-уведомлений отдельно не переделывался.

## Ограничения измерений r57

В изученном r57 нет CPU/RAM и image fingerprint в телеметрии. Поэтому интерфейс не рисует фиктивные `0 Б / 0 Б`, загрузку 0% или совпадение образов по одному имени. Существующий контейнер доказывает наличие образа, но не равенство версии между нодами. Матрица показывает «Есть · без сравнения». Когда реальные fingerprints присутствуют в совместимом формате, сравнение работает.

Точные CPU/RAM, hostname/температура, подробные WAL-метрики или сравнение fingerprints требуют их измерения и передачи агентом; одно оформление страницы их не создаёт. Для уже реализованных IP, edge, диска и состояний контейнеров r57 достаточно.

Количество доступных агентов с правом голоса подписано как доступность участников; это не отдельная проверка кворума etcd.

## Проверки после развёртывания

На странице проверить: сервер A выбран корректно; адреса совпадают с топологией; у B/C сохранены standby и нужные профили; Cloudflare указывает на актуальную Primary. Передвинуть B, обновить страницу — позиция должна сохраниться. Проверить поиск контейнеров, сеть и адреса. Для C исключённые из полного списка услуги не должны становиться «отсутствующим образом».

API теперь отдаёт `schemaVersion: 2`. При старом API фронтенд сообщает о необходимости обновления `observability-api`, вместо выдумывания недостающих данных.

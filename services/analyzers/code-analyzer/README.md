# taskforge-code-analyzer

Небольшой сервис для **быстрой статической проверки** решений перед запуском (stage 1).

## Что делает
- Получает `language` + `source`.
- Для системной security-policy удаляет комментарии и строковые литералы, чтобы не ловить запреты внутри текста.
- Учебные `required_calls` / `forbidden_calls` разбирает по форме правила: вызовы и идентификаторы проверяются без строк/комментариев, многословные типы вроде `long long` — как последовательность токенов, а явные format-string правила вроде `%.2f`, `%lld` и `%%` — с сохранением строковых литералов, но без комментариев.
- Ищет запрещённые конструкции (inline-asm, eval, запуск процессов, файловые/сетевые API и т.д.).
- Блокирует кириллицу в исполняемом коде, но разрешает её в комментариях и строковых литералах. Это особенно важно для Pascal/C++: русские имена переменных дают неочевидные ошибки компилятора.

> Системная security-policy остаётся fail-closed. Учебные правила не являются полноценным AST-контрактом, но для идентификаторов, вызовов, многословных token-фраз и format-string фрагментов используются разные безопасные стратегии сопоставления вместо одного сырого substring-поиска.

## API
- `GET /health` → `ok`
- `POST /analyze`

### Request
```json
{
  "language": "cpp",
  "source": "...",
  "extra_forbidden": [
    {"id":"no_sort","needle":"std::sort","description":"Запрещён std::sort"}
  ]
}
```

### Response
```json
{
  "ok": false,
  "errors": [
    {"code":"forbidden","message":"Запрещён inline-assembler (asm)","pattern_id":"c.asm"},
    {"code":"cyrillic_in_code","message":"Кириллица разрешена в строках и комментариях, но запрещена в исполняемом коде: используйте латинские имена переменных, функций и классов.","pattern_id":"unicode.cyrillic_in_code"}
  ],
  "hits": [
    {"pattern_id":"c.asm","needle":"asm","position":123,"preview":"..."}
  ]
}
```
